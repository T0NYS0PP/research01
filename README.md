# スマレジ 品番別 継続・終売判定

スマレジの「商品別売上」「月別売上」CSVから、品番（スタイル）ごとに **再生産・継続・アップデート・終売** を判定し、HTMLレポートを作ります。

> 売上データと出力（`data/`, `output/`）は `.gitignore` で除外しています。このリポジトリは公開設定なので、CSVやレポートはコミットしないでください。

## 使い方

```bash
pip install -r requirements.txt
python3 run_analysis.py \
  --prev  商品別売上_20250101-20251231.csv \
  --curr  商品別売上_20260101-20261004.csv --curr-start 2026-01-01 --curr-end 2026-10-04 \
  --monthly 月別売上_202411-202510.csv 月別売上_202511-202610.csv \
  --out output/
```

- `--prev`：前年1年分の商品別売上（管理画面の書き出しそのまま。Shift_JISのままで可）
- `--curr`：今年1月1日から判定日までの商品別売上
- `--monthly`：前年1〜12月を含む月別売上。前年12月が締まった後に書き出したものを使ってください（前年の商品別売上と合計が一致しないと止まります）
- `--params`：パラメータを上書きするJSON（例：`{"Q_LINE": 0.6, "COVER_REORDER": 30}`）
- `--stability-runs`：安定度の再判定回数（既定200回、数分かかります。0で省略）
- `--report-only`：既存の出力からレポートだけ作り直す

集客データ（任意）：`--tracker tracker.csv --activity activity.csv` を付けると、認知KPI週次トラッカーの数値と店舗の売上を並べた「集客データとの照合」がレポートに加わります。どちらも日曜はじまりの週を1行とするCSVです。

- `tracker.csv`：`week, gsc_impr, gsc_clicks, gsc_ctr, gsc_pos, ig_reach, ig_impr, sessions, followers, ig_sessions`
- `activity.csv`：`week, ig_posts, newsletters, social_sessions, email_sessions, sessions, checkouts, conv_rate, sales_incl_store, from, to`（`from`/`to` は一部の日だけ計測した週の計測日。ふだんは空欄）

判定終了日（`--curr-end`）までに終わっていない週は自動で除外されます。

出力：`report.html`（レポート）、`style_decisions.csv`（全品番の判定・理由・指標、Excelで開けます）、`dead_skus.csv`、`series.csv`、`other_brands.csv`、`break_point_lines.csv`、`run_meta.json`。

## 判定のしくみ

**分岐点**：その品番の棚と生産枠を「典型的な新商品」に渡したときの粗利を下回ったら、販売をやめる。

1. 棚グループ（Tシャツ・アウター・パンツ・キッズ・帽子/バッグ/靴・小物など）ごとに、今年初めて売れた新商品の初期粗利の中央値を **分岐点ライン（H50）** とします（Harrell–Davis推定。新商品が少ない棚は価格帯モデルで補強）。
2. 既存品の今期粗利をこのラインと比べます。秋冬寄りのトップスは季節補正し、棚の平均より安い商品は同じ価格帯の新作と比べるためラインを下げます。
3. 売れ筋のサイズ・色が欠品している品番は、前年の実績（同期間換算）も使って判定します。欠品日の目安として「仮想欠品日」を出すので、スマレジの在庫履歴で確認してください。
4. 前年はライン超えなら **アップデート（デザイン刷新）**、+15%以内の値上げで届くなら **アップデート（価格・原価）**。どれでも届かないときだけ **終売** です。
5. 新商品・前年後半投入・秋冬物は期間が短いので **様子見** にします。

| 判定 | 意味 |
|---|---|
| 再生産 | ライン超えで、欠品中（即手配）か、ピーク前の在庫が3週間分未満（追加発注） |
| 再生産・復刻（要確認） | 前年は売れたが欠品で今期が伸びていない。欠品日で同型か刷新版かを決める |
| 継続・強化 | ライン超えで在庫も足りている |
| アップデート | 需要の土台はあるが勢いが落ちている、または粗利率が低い |
| 様子見 | 新商品・前年後半投入・成長中など。次回の判定で再評価 |
| 終売（在庫消化） | 2年ともライン未満で救えない。在庫を売り切ったら作らない |
| 終売済み | 在庫0でライン未満。再生産しない |
| 他社ブランド別管理 | 原価未登録の他社ブランド（ETC1）。掛率を登録すれば同じ物差しで評価できる |

すべての閾値は `smaregi_analysis/params.py` の `DEFAULT_PARAMS` にあります。部門と棚グループの対応、シリーズ名、コラボ判定のキーワードは `smaregi_analysis/taxonomy.py` で編集できます。

## 精度を上げるデータ

- 商品別売上の月別書き出し（品番ごとの季節性・発売月・欠品月がわかる）
- 在庫変動履歴（欠品日数と本当の消化率がわかる）
- 売上0のSKUも含む在庫一覧、商品マスタ（登録日・旧品番との対応）、生産リードタイム、他社ブランドの掛率
